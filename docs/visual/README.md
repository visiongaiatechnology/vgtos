# VGT Omega — Glass 2100 console: visual evidence

## Status: VISUAL_QA = NOT_TESTED (screenshots blocked by the build environment)

**No PNG screenshots exist in this directory, and none are claimed.** Chromium and Firefox cannot
start inside the confined build environment used for this release: process creation and the
internal browser IPC are denied. Every attempted capture failed before a frame was rendered:

```
[FATAL:mojo\public\cpp\platform\platform_channel.cc:112] Check failed: . : Zugriff verweigert (0x5)
```

Tested and reproducible with:

- `chrome.exe` — `--headless=new` (all three viewports): same failure, exit 13, no PNG.
- Headless Chrome shell — `--headless --single-process`: same failure.
- `firefox.exe -headless -screenshot`: process start denied (`Zugriff verweigert`).

The environment restriction was **not** bypassed. What was produced instead is the real rendered
markup plus static audits; pixel-level review is explicitly open.

## What is here

| File | What it is | How it was produced |
|---|---|---|
| `dashboard-preview.html` | Healthy console: 3 artifacts (2 mounted, 1 locked), success notice, full diagnostics | `php tests/visual/render-dashboard.php` |
| `dashboard-preview-safe-mode.html` | Safe mode + boot failure: offline banner with opaque reference, safe-mode recovery snippet, empty registry, disabled deployment, unavailable telemetry, error notice | same command |
| `dashboard-preview-dialog.html` | Same as healthy state with the Z4 delete-confirmation `<dialog>` opened by the shipped `console.js` | same command |
| `contrast-audit.md` | 29 WCAG 2.2 AA contrast pairs computed from the declared sRGB tokens | `php tests/visual/audit-contrast.php` |
| `static-a11y-audit.md` | 87 DOM/semantics checks + 32 source/dependency/design-rule checks + PHP line ledger | `php tests/visual/audit-static.php` |

The previews are generated by the **production render path**
(`Dashboard::renderWith(ConsoleData::fromFixture(...))`) with WordPress functions stubbed in
`tests/visual/render-dashboard.php`. No WordPress install and no booted `VaultManager` is required.
They link `../../src/UI/Dashboard/assets/glass-2100.css` and `.../console.js` by relative path, so
opening the HTML file in a browser shows the real stylesheet and real interaction layer.

## Reproduce

```powershell
# 1) Render the three preview documents (WordPress stubs only)
php tests/visual/render-dashboard.php

# 2) Static audits (must exit 0)
php tests/visual/audit-contrast.php
php tests/visual/audit-static.php
```

## What remains unverified (honest list)

- Real browser paint of the OKLCH/glass composites, backdrop-filter and shadow model.
- Screen-reader announcement order and accessible-name computation in a real assistive technology.
- Touch target feel, virtual keyboard, safe-area insets, landscape/narrow-height behaviour.
- 200 % text zoom reflow and `prefers-reduced-motion` / `prefers-reduced-transparency` /
  `forced-colors` behaviour in a live browser (the rules exist and are statically checked).
- The delete-confirmation interaction end-to-end in a browser (dialog focus trap/restore, Escape,
  form submission after confirmation). The code is source-reviewed only; the rendered dialog markup
  is in `dashboard-preview-dialog.html`.
